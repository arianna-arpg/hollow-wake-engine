# Unity native cleanup patch

The gameplay 0.4.1 preview replaces the native library in the exact published
0.4 archive. It fixes the pinned QuickJS-NG CString allocation-failure cleanup.
Every script, content file, GUID and license notice is byte-identical to 0.4.
Only the library and package version change; an ignored documentation file
records native provenance. Storage 0.3 is optional and remains unchanged.

The exact candidate DLL passes C++ and C# ownership/cancellation/unload contracts
and all 579 frozen shared-account replies. With a 32 MiB cap, both original and
repaired runtimes fail the same workload and reject reuse. The original leaves
86,410 tracked bytes at destruction; the repair leaves zero. Both complete the
48 MiB course. This is cleanup qualification, not a claim that the larger course
fits 32 MiB. Shared-account composition is not added to the Unity archive.

Three 450-command workshop courses exercise the exact repaired DLL with no
explicit collection, one collection after configuration, and collection after
each response. Replies match throughout and each host releases all tracked
allocations. The native ABI exposes collection but the unchanged Unity binding
does not install an automatic policy. Timing and physical-device budgets remain
unmeasured.

The final tarball passes Unity 2021.3.6f1 Windows x64 Mono editor and relocated
player checks: 104 account progression replies, 60 combat replies, 2,334 pouch
replies and 56 workshop replies per run. Equipment publication preserves live
combat and restores the exact revision-seven save. Durable account/workshop
courses pass complete-state comparisons, cancellation, stale/busy refusal,
post-commit failure closure, five lifecycle courses, imported examples and four
deliberately broken storage packages.

Fourteen damaged runtime receipts and thirteen archive controls pass. The
complete SDK/reference verification remains the executed shared-account r5
receipt with unchanged SDK sources; it is not regenerated by this native-only
patch. The initial runtime/package receipts stay local under their original
hashes. `prior-attempts.json` identifies the stricter source-inventory rebuild and
the missing-fixture setup failure. Neither is relabeled as the final run.

`acceptance.json` binds current sources and evidence. `reports.json.gz` retains
complete reports; `native-raw.json.gz` and `collection-raw.json.gz` preserve full
caller replies. `observations.json.gz` contains engine outputs and only the
relevant assertion lines from failed controls. Unity logs remain local because
they contain machine/licensing diagnostics; `redactions.json` identifies them.

The independent [hosted Windows build](https://github.com/arianna-arpg/hollow-wake-engine/actions/runs/42516685945)
passes the same native, receipt, collection and packaging gates. Its receipts and
log are retained here; its complete downloaded artifact is the release asset
`hosted-runtime-qualification.zip`, pinned by `acceptance.json`. That build has
a different DLL hash and is reproduction evidence. The shipped gameplay archive
is the local DLL/package actually exercised in Unity; hosted success is not
substituted for engine acceptance.

Run `node scripts/check-unity-cleanup-evidence.mjs`. Add `--runtime DIRECTORY
--archive ARCHIVE` to verify the retained DLL and actual release archive too.
The [build recipe](../../experiments/embedded-js/patches/qualified-runtime.md)
describes reproduction. Linux engine packages, IL2CPP, ARM, Steam Deck and older
mobile devices need separate acceptance. The overall SDK completion goal is
still active.
