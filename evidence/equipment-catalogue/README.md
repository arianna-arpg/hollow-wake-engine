# Original equipment catalogue checkpoint

This checkpoint records **18,773 original derivation cases in two fresh
processes**, exact SDK item-modifier agreement for every case, and six detected
observer faults with matching unchanged controls. It changes no production
runtime or published native package.

The [boundary and findings](../../docs/equipment-catalogue-boundary.md) distinguish
static derivation from action authorization, complete effect execution, legacy
state migration and native/device acceptance.

| File | Recorded evidence |
| --- | --- |
| `../../baseline/equipment-catalogue/acceptance.json` | Original source/exporter hashes, source counts, coverage and every exclusion |
| `../../baseline/equipment-catalogue/observations.json.gz` | Raw JSON observations, compressed without changing their content |
| `reference.json` | Two-process capture result and verified cleanup/source preservation |
| `audit.json.gz` | All SDK compilation and numeric-projection comparisons, rejection reasons, derived-state cases and 48 original choice fallbacks |
| `observer.json` | Six original-port fault detections and hashes of fresh matching controls |
| `acceptance.json` | Tool/evidence hashes and the unchanged SDK runtime commit used for the audit |

The numeric primitive matches the observed arithmetic in 271 cases and refuses
18,502. Those refusals are remaining gameplay capability, not lost item content:
all 18,773 modifier arrays match the original. Worn support rows, granted-skill
ownership, class bonuses and saved item mutations require additional composition.

`acceptance.json` records local Windows x64 Node 24.9.0 execution. The dedicated
`Verify original equipment catalogue` workflow reproduces the course on Windows
and Linux; a workflow file alone is not hosted acceptance. Consult its actual run
before making a hosted claim. No physical-device or new engine-package result is
implied.

Run the three commands in the boundary document after the normal SDK build and
pinned-reference preparation. Normal checks read the existing expected fixture;
they cannot replace it. The six fault checks inject omissions into temporary
exporter copies at actual original-game ports, preserve every original source
file and delete their temporary scripts/results on success and failure. Their
scope is observation sensitivity, not exhaustive source mutation coverage.
