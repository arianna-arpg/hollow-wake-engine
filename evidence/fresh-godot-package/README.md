# Fresh Godot package qualification

The canonical crafting builder omitted the vestige entry file and selected
the older support bundle. Previously verified overlay deliveries concealed
this independent build-path defect. A fresh progression package reproduced
the missing-entry failure before the repair.

The builder now installs the matching SDK, builds the complete workshop
entry point, verifies the minified bundle through its numeric wire protocol,
and requires two capability faults to fail. Its temporary consumer is removed
even when archive assembly fails. Existing accepted pointers survive failed
builds. No previous workshop archive supplies code or content to this path.
The native base extension and matching embedded library remain hash-verified
inputs; their implementation did not change.

The inventory package includes the current background-saving profile, station
UI and opt-in verification fixtures. Both editor and freshly extracted player
must complete background saving/reopening, all 79 station assertions and
inlay/reopening. The recorder compares exact original checkpoints after each
forced process shutdown, rather than requiring a nonempty precommit WAL.
Four receipt faults prevent partial or missing evidence being accepted.

## Scope

Windows x64, Godot 4.7.2 and the pinned SQLite/native toolchain. No new runtime
mechanics, gameplay balance or original game files changed. The fresh bundle
is 113,812 bytes; the original 56-command native course peaked at 32,382,604
tracked bytes, within its 33,554,432-byte per-host cap. These are allocation
and bundle-size observations, not total process memory or a speedup claim.

Linux fresh-build qualification, physical Steam Deck/mobile performance and
Unity/Unreal integration remain separate work. Earlier Linux overlay evidence
does not establish this revised pipeline's Linux result.
The older Steam Platform inventory runner still expects a rollback-journal
file at its crash barrier; that separate runner needs WAL-aware recovery
qualification before claiming a fresh Linux end-to-end result.

## Reproduce

Follow the build, replay and record sequence in
[Godot crafting](../../docs/godot-crafting.md), then:

```text
node scripts/verify-inventory-workshop.mjs --tools <tools.json> --addon <fresh-combined-addon.zip> --addon-proof <fresh-native-evidence/windows.json> --sqlite <pinned-sqlite.zip> --out <new-delivery-directory>
```

This command builds the current save extension, packages the inventory,
checks UI/custody/crash recovery and current workshop courses, then runs
receipt controls, project identity, delivered rack/support/recall/view courses
and station fault controls. The requested delivery appears only after all
checks pass; use the checkout's volume for that final atomic rename. Keep the
original reference captures immutable.

The accepted local run and retained artifact hashes are in `acceptance.json`.
The original 56 native replies are retained separately from the new assertions;
none of the expected original outcomes were regenerated by the extracted SDK.
