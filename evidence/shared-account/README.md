# Shared account authority checkpoint

This checkpoint qualifies the portable account/workshop owner. One account owns
progression, expertise and counters across multiple character inventories.
The [contract](../../docs/shared-account.md) defines authority, save identities,
transaction boundaries, limits and the required engine integration.

The source observer preserves two accepted revisions. The first contained an
artificial crafted socket on a zero-capacity ring. It is retained unchanged.
The corrected revision uses a socket-capable helmet, records its later capture,
and is compared against the same pinned original rules. Both revisions detect
all nine deliberate source faults. No accepted result is regenerated by tests.

The corrected 10 scenarios and 30 steps match complete account/inventory states,
purchase results, selected offer visibility, capacity and random draw counts.
Independent contracts cover attached inventories, separate accounts, sealed
characters, save continuation, refused competing authority, detached snapshots,
no-op versions, random overflow, hostile inputs, owner limits and combined
serialization admission and explicit nulls. All 22 run in both an installed package and a browser
bundle with ambient RNG and host globals disabled. Fourteen deliberately broken
authority variants fail behavior assertions; the restored implementation passes.

The core size limit remains 96 KiB. The optional owner has a separate 20 KiB
unminified-code limit; the complete optional browser bundle is limited to 180 KiB.
These are code-size limits, not VM or engine memory claims.

## Native result remains unaccepted

The separate diagnostic uses the exact native DLL from the public Unity
progression 0.4 preview and newly bundled shared-account rules. At a 32 MiB
allocator cap, the catalogue query in the fourth scenario poisons the host with
script-error status 4. Destruction returns leak status 11 with 86,410 requested
bytes still tracked. The peak is 33,493,285 bytes, close to the 33,554,432-byte cap.
The exception is out of memory. A separate private investigation traced the
retained allocation to the pinned runtime's string-conversion failure path.
The cleanup candidate and collection-policy experiments are not accepted by
this checkpoint; this evidence deliberately retains the unchanged public
library's failing result. See the contract for the investigation boundary.

At 48 MiB, all 579 native command replies match, peak requested allocation is
36,140,101 bytes, and destruction reaches zero. That successful configuration
does not erase the failed configuration or qualify an engine package.
The portable acceptance and native failure are separate fields in this evidence.

The host allocator excludes its prefixes, system allocation overhead, caller
buffers and game-engine memory. No elapsed-time or physical-device conclusion is
claimed. The new composition has not been installed in the public engine
packages. Native cleanup, memory optimization, legacy-account migration and
durable engine publication are the next gates.

Run `node scripts/check-shared-account-evidence.mjs` to check source bindings,
the full SDK/reference receipts, both source replays, installed/browser controls
and the retained native failure. Diagnostic reproduction is documented in the
contract. Scratch consumers are removed after their receipts are retained.
