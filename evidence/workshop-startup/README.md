# Workshop startup collection experiment

The published Unity gameplay 0.2 and storage 0.1 archives are unchanged.
This experiment compares five collection schedules in a native measurement
executable using the pinned QuickJS-NG 0.17.0 sources, the existing host source,
the exact gameplay archive and the frozen workshop replay.

All 15 fresh-process runs produced the same 56 gameplay replies, plus two
configuration replies. Every host released its tracked allocations. A changed
reply was rejected, and a separate forced preparation failure verified that its
temporary build directory was removed.

| Schedule | Bytes immediately after collection | Bytes at replay end | Peak tracked bytes |
| --- | ---: | ---: | ---: |
| Existing behavior; no explicit collection | 28,178,613 | 29,011,205 | 32,811,005 |
| Collect after creation | 18,068,845 | 31,123,389 | 31,859,444 |
| Collect after configuration | 18,554,661 | 31,139,181 | 31,863,116 |
| Collect after creation and reset threshold | 18,068,845 | 24,897,669 | 30,947,365 |
| Collect after configuration and reset threshold | 18,554,661 | 22,741,285 | 30,947,365 |

The configured host holds 28,660,357 tracked bytes immediately before collection.
Counts are identical across all three repetitions of each schedule on this
recorded Windows x64 build. They exclude allocator headers, CRT overhead, caller
buffers, Unity, managed memory, SQLite and other process allocations.

This isolates a tradeoff: collecting alone reduces startup retention but leaves
more bytes at the end of this course. The threshold variants also reduce the
recorded replay peak by 1,863,640 bytes (about 5.7%). They do not reduce the
30,947,365-byte content-loading peak. These are workload-specific native
allocation observations, not device-memory or frame-rate results.

The pinned runtime's automatic collection path resets its trigger to allocated
memory plus half that amount; a direct collection call does not perform that
reset. The experiment copies that policy through public memory/threshold APIs.
The general mechanism is described in the upstream
[QuickJS-NG internals](https://quickjs-ng.github.io/quickjs/developer-guide/internals/#garbage-collection);
the authoritative implementation for this experiment is the hashed
[0.17.0 source](https://github.com/quickjs-ng/quickjs/blob/v0.17.0/quickjs.c).

Elapsed times are retained for diagnosis only. They varied substantially under
uncontrolled desktop load; no startup-speed or steady-state CPU claim is accepted.
The regular SDK benchmark measures a separate contact kernel and would not
establish the cost of this collection policy.

## Decision and remaining evidence

Keep this as research. Do not insert a collection into every frame or change
generic host behavior solely from this course. A shipping change needs an
explicit quiescent lifecycle boundary, bounded ownership, pending-response and
failure semantics, representative long-lived inventory workloads, and actual
Unity/Godot editor and player validation. Weak references/finalization and
asynchronous-job rejection also need an explicit compatibility decision.
Steam Deck, older mobile hardware, Linux and ARM measurements remain open.

The measurement executable includes the existing C host solely to access its
runtime in an isolated process. It does not add a shipping ABI entry point,
change a package, or overwrite a native library.

## Reproduce

Supply the source files matching the committed host lock and the exact public
[gameplay 0.2 archive](https://github.com/arianna-arpg/hollow-wake-engine/releases/tag/unity-workshop-v0.2.0-preview.1).
Build output and reply streams are removed on success or failure; only the
requested report and compressed source/build record remain.

~~~text
node scripts/probe-workshop-startup.mjs --amalgam-dir <pinned-source> --package <gameplay.tgz> --python <python> --output <fresh-report.json>
~~~

The source supports the existing Windows/Linux x64 development toolchains.
Only the recorded Windows run is qualified here. Accepted replay files are
read-only and never regenerated by this command.
