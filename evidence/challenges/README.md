# Challenge controller qualification

The optional controller and content assembly pass 126 verification commands,
2,195 unit tests and all 51 reference commands. Twenty installed/browser-bundle
contracts, eight negative type cases and sixteen deliberate package faults
qualify their public boundary. The installed game reproduces all 61 accepted
observations, rejects six altered source inputs and detects six runtime/adapter
faults. Its fully composed game matches the original challenge control, the
frozen original observations, all three type configurations and 25 paired
combat episodes. Browser-target bundles execute in an isolated Node VM with
forbidden host globals; this course does not run a rendered browser.

The initial original probe missed retained-cast identity, and the first
carrier-removal fault was masked by separate World cleanup. Five focused
identity/retirement checkpoints close those gaps. Supplemental randomness has
its own seed; the original 56 checkpoints remain unchanged. Earlier failed
captures, the candidate type repair, exact prototype sources and restored
checks are retained in the compressed prototype archive. The production
controller body is identical to the qualified candidate.

This module preserves authored Goad mechanic identities. The host-supplied
`deviceCall` definition must retain `goad_device_call`. Each owner has one
active challenge investment per skill-definition ID: preparing another host
for that key retires the former investment. These are existing game rules,
not a claim that arbitrary ability names or duplicate investments are admitted.

Normal checks read immutable accepted observations. Historical capture tools
are evidence of baseline preparation and are not a normal recapture command.
Use the four maintained commands in docs/challenges.md for reproduction.

The runtime/content group is 19,170 emitted bytes, bounded separately at
20 KiB. The minified browser consumer is 11,243 bytes, below 12 KiB. Earlier
package limits remain unchanged. These are code-size observations, not CPU,
allocation, whole-frame or physical-device performance claims.

The complete adapter checks the original challenge source before changing
game files. Tests clean their own workspaces even when integrity verification
fails. Verification workspaces and generated package archives were removed;
no worktrees were created. Existing worktrees and historical archives remain.

Private challenge continuation, complete authored character construction,
durable live publication, native bindings and device qualification remain
open. The project goal is not complete.
