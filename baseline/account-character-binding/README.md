# Original account and character binding

Twelve checkpoints were captured from the pinned original source before the
new SDK authority implementation. Two fresh processes produced identical bytes;
the observer and source lock hashes are recorded in `acceptance.json`.

The course records canonical board order, carry versus board, guest/client/host
roles, different-scope ordinary-item collisions, repeated character adoption,
disabled relics, possession through the home hero, release and stale-character
restoration. It records complete canonical bodies, projection aliases, source
modifiers and character serialization rather than UI descriptions.

Creating a second original World installs a global container-board source.
The observer explicitly restores the first World's lookup before returning to
it. The first draft failed its optional-save TypeScript check; a later draft
exposed this global dependency. Neither draft produced accepted expectations.
The corrected original observer, unchanged source lock and two matching fresh
outputs establish this baseline. No SDK candidate generated expected values.

`npm run reference:account-character-binding` reproduces and compares the
accepted bytes. It has no capture mode, checks the complete original game types,
uses isolated scratch files and removes them on success or failure.

Original migration may readdress canonical UIDs. The new strict account owner
instead rejects ambiguity without discarding bodies. Diagnostic SDK investment
writes are separate from this original course: these authored relics grant
companions and do not prove ordinary skill-grant investment behavior.
