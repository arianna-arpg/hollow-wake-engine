# Bounded stat context cache

`@hollow-wake/engine/stats/context-cache` exports `TagContextCache<Key>`. It
reuses an encoding of a set of string tags without retaining the caller's set.
The SDK `StatSheet` uses it internally; callers using the stat API need no changes.

```ts
import {TagContextCache} from '@hollow-wake/engine/stats/context-cache';
const contexts = new TagContextCache(tags => JSON.stringify(tags), 16);
const tags = new Set(['spell', 'fire']);
const key = contexts.get(tags);
tags.delete('fire');
tags.add('cold');
const changedKey = contexts.get(tags);
```

The encoder receives an owned, frozen, sorted array on a miss. It must be pure;
its result must be treated as immutable. A hit checks cardinality and membership,
including for same-size mutations, new equivalent sets, and live readonly views.
`ReadonlySet` and `Object.freeze(set)` do not imply immutable set membership.
Neither set identity nor an unchecked cached hash is sufficient here.

The default retains at most 16 nonempty contexts and one empty encoding. Capacity
must be a nonnegative safe integer; zero disables nonempty retention. Round-robin
eviction bounds storage, with a recent-context fast path. `clear()` forgets the
nonempty contexts. Encoder failures do not insert or evict an entry. These are
entry bounds, not byte bounds: tag lengths and the encoder's result size remain
the caller's responsibility. High context churn still pays for sorting and a
bounded scan; this is intended for repeated gameplay contexts.

`StatSheet` accepts the context budget as its optional third constructor argument,
after the existing stat rules and value-cache budget. Defaults are 256 value
entries and 16 context entries. Context storage is created lazily for cacheable,
nonempty queries and survives value invalidation. `contextCacheEntries` reports
its retained nonempty count. Values with extra modifiers or base overrides keep
their existing bypass behavior. Length-prefixed stat identifiers and JSON tag
encodings distinguish arbitrary identifiers, separators, quotes and Unicode.

The cache module has a separate 3 KiB unminified JavaScript growth guard. It is
still counted in the retained 96 KiB core and 674 KiB whole-package limits. The
historical component budgets exclude this new file; changes in `stats.js` remain
charged to those budgets.

## Original-game boundary

The game adapter replaces only repeated sorting/joining of stat context tags. It
preserves the original stat fold, invalidation, links, and value cache, including
the original comma-key alias for `['a,b']` and `['a', 'b']`. That legacy behavior
does not become the SDK's encoding policy. The game's existing value cache remains
unbounded; the added context cache has the independent 16-entry bound.

The frozen original baseline contains 74 courses covering mutable sets, key
ordering and aliases, cache bypass, links, invalidation, and eviction/revisits.
Two original runs, the predecessor adapter, the prototype, and Node 22 agree.
Accepted expectations are never regenerated by ordinary verification.

## Verification and measurement

Run `npm run reference:stat-context`, `npm run test:stat-context-observer`,
`npm run adapter:stat-context-source`, then prepare a fresh adapter and run
`npm run adapter:stat-context` and `npm run adapter:stat-context-faults`.
`npm run verify` includes the independent tests, clean installed consumer,
browser/types checks, and runtime mutations.

`npm run benchmark:hit-paired -- --previous <location.json> --location
<location.json>` alternates two persistent workers for 12 pairs per workload.
Both receive equal warmup, hit counts, reset work, and deterministic inputs.
Every pair compares gameplay observations. After timing, the established whole-hit
observer independently checks the total course. An identical-input control exposes
noise; reports retain every pair and input hashes. IPC, cross-worker comparisons
and explicit GC are outside timing; the existing per-hit alive assertion remains
inside both measured paths. Retained heap is not total allocation volume.

`node scripts/test-hit-paired-observer.mjs --location <location.json>` deliberately
skips a hit or alters a draw count in both timing workers. Their peer comparison
still agrees; the independent established observer must reject each fault. Run
this after a successful paired benchmark, which supplies the positive control.

Profiling identified repeated stat-key work in the existing game host. The cache
targets that measured cost, without database queries in the hit loop. Prototype
measurements are exploratory; final installed measurements and their limits belong
in the milestone evidence. Windows host results do not establish Steam Deck or
older-mobile performance, and no allocation-free or universal speedup claim is made.

The final installed Windows x64 comparison on an Intel i9-10900K measured the
following median paired ratios (new time divided by previous time). Each workload
had 12 pairs of 1,000 hits after 1,500 warmup hits per worker. The optimized worker
was lower in all 12 pairs for every workload. Both workers matched each other and
the independent established observer on gameplay results.

| Workload | Identical-input control | Installed cache / previous |
| --- | ---: | ---: |
| Plain hit | 0.987 | 0.754 |
| Authored status | 0.997 | 0.771 |
| Stat-granted status | 0.958 | 0.750 |
| Next-hit rider | 1.059 | 0.847 |
| Impale | 1.020 | 0.834 |

These are 15–25% lower median times for the five measured warm workloads on this
host. They do not establish a universal gain, high-churn performance, frame rate,
total allocation volume or device acceptance. The retained
[evidence](../evidence/stat-context/runtime-windows.json) includes every pair,
the prototype run, identical-input control, deliberate observer faults, source
hashes, native diagnostic repair, and rejected validation attempts. The 1,209-test
SDK verifier, 18 game validation groups and complete native attack replay pass
locally. Hosted checks for the published revision are tracked separately.
